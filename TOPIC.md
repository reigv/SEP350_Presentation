## Preferred Topics (in order)

### 1. Graph Databases and Social Network Analysis
**Why:** Graph databases are good at storing data that's all about connections. Relational databases put data in tables. Graph databases store it as nodes (things), edges (links between them), and properties (details about each). That makes the structure flexible.

**Sources:**
- https://medium.com/@17nagh/graph-database-genai-980c71ff3384
- https://cambridge-intelligence.com/blog/choosing-graph-database/
- https://nebula-graph.io/posts/social-networks-with-graph-database-1

### 2. NoSQL Databases
**Why:** NoSQL databases are non-relational, which means they don't store data in tables. They're best for large amounts of data spread across many servers. They're grouped by data model, and the main types are document, key-value, column, and graph.

**Sources:**
- https://medium.com/@fullstacktips/nosql-databases-explained-59fbfbbef396
- https://medium.com/paragoncloudconsulting/relational-vs-non-relational-a-complete-guide-to-sql-and-nosql-databases-c1e0023b130f

### 3. Database Security and Privacy
**Why:** Database security is about protecting a database from attacks, unauthorized access, and breaches. It keeps data private, so only the right people can see it, and accurate, so it isn't changed or lost. It combines technical tools, like passwords and encryption, with company rules and policies.

**Sources:**
- https://saniking6772949.medium.com/understanding-database-security-protecting-your-data-in-a-digital-world-8523b8736921
- https://www.red-gate.com/blog/database-design-for-security/
